焼きなましの経過

横軸は計算時間 (ms)、縦軸は操作数。帯は各区間での現在解の最小〜最大、太線は best。焼き終えたあとグラフ上をなぞると、その時刻の best を盤に出します。

自分の出力を再生

入力ファイルと出力ファイルの中身を貼ります。公式ルールのシミュレータで検証し、正しければその解を盤で再生します。ファイルを欄にドロップしても読み込めます。操作数が T を超える出力や、盤外へ出る出力は、行番号つきで理由を示します。入力欄には今のケースが入っています。

解法のしくみ

状態
魔法陣の初期配置 3 点と、150 個の区間ごとの「使う陣 (なし / 3 つのどれか)」「跳ぶ直前の位置」を持ちます。区間 i は、前の目的地 (最初は s) から g_i までの移動です。
近傍
次の 3 種類を 1/3 ずつの確率で選びます。陣の初期配置を 1 つ動かす。ある区間で使う陣を変える (なしにもできる)。ある区間の跳ぶ直前の位置を動かす。点の移動は 1/8 の確率で盤上の一様ランダムな点へ、それ以外は縦横に −8〜8 ずらします。
評価
操作数を先頭から数え直します (計算量 O(M·K))。区間ごとに、跳ぶ直前の位置まで歩き、1 手で転移し、目的地まで歩きます。転移で使った陣は、跳ぶ直前の位置に移ります。盤外に出る解は捨てます。
転移
現在地 (i, j) から陣 (a, b) で跳ぶと (i, j) → (2a − i, 2b − j) に着きます。使った陣は消え、(i, j) に新しい陣が描かれます。
温度と受理
温度は T0 · (T1 / T0)^progress で、progress は計算に使った時間の割合です。既定は T0 = 30、T1 = 1。操作数が増えない変更は必ず受け入れ、増える変更は exp(gain / 温度) の確率で受け入れます。
出力
得られた状態を、区間ごとに「跳ぶ直前の位置へ歩く、J、目的地へ歩く」と展開します。歩くときは縦を先に、横を後にします。

C++ の解法を JavaScript に移植して、この画面の中で動かしています。乱数と時計が C++ と別なので、同じ seed でも得られる解は一致しません。ケースは seed から作り、検証は公式ルールを再現した別実装です。
