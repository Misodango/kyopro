AHC パラメータ調整

焼きなましの温度やビームの評価関数の重みを、多数の seed で回して自動で決めるための道具です。置き場所は ~/kyopro/ahc/。コードの値は環境変数で上書きでき、ジャッジ上では既定値が使われます。

本番の流れ

acc で作った a/ に公式ツールを展開して tools/ にする。コマンドはすべて a/ で打つ。

  1. ツールをビルドする

    インタラクティブなら tester、そうでなければ vis ができる。run.py はどちらがあるかを見て採点方法を変える。

    cd tools && cargo build -r && cd ..
  2. コンパイルする

    出力は ./a.out。別名にしたときは run.py / tune.py に -c ./名前 を付ける。

    g++ -std=c++20 -O2 -I ~/kyopro/ac-library main.cpp
  3. 基準を保存する

    今のコードの結果を runs/base.json に残す。コードを直すたびに名前を変えて保存しておくと後で比べられる。

    python3 ~/kyopro/ahc/run.py -s 0-49 --save base
  4. 手で 1 つ試して比べる

    K=V は環境変数 P_K として渡る。基準比の平均と勝敗数が出る。

    python3 ~/kyopro/ahc/run.py -s 0-49 --base base T0=30
  5. 自動で探す

    TL を短く固定して試行回数を稼ぐ。Ctrl-C で止めても、それまでの最良を表示する。

    python3 ~/kyopro/ahc/tune.py T0=1:1000:log T1=0.01:10:log TL=500 -s 0-29 -n 50
  6. 別の seed で確かめる

    tune.py が最後に出すコマンドをそのまま打つ。元の TL で回すこと。seed 100 以降の入力は gen で先に作る。gen は seed ではなく seeds.txt の行番号でファイルに名前を付けるので、100〜199 だけを書くと in/0000〜0099 が上書きされる。0〜199 を全部書けば、0〜99 は元と同じ入力になり 0100〜0199 が増える。

    cd tools && seq 0 199 > seeds.txt && cargo run -r --bin gen seeds.txt && cd ..
python3 ~/kyopro/ahc/run.py -s 100-199 --save def
python3 ~/kyopro/ahc/run.py -s 100-199 --base def T0=37.2 T1=0.41
  7. コードの既定値に書き戻す

    tune.py が出す param("T0", 37.2) の行で、コードの既定値を置き換えてから提出する。ジャッジに環境変数はないので、書き戻さないと効かない。

param() を入れる

sa.cpp / beam.cpp / chokudai.cpp には最初から入っている。新しく書いたコードでも、この関数を貼れば同じように使える。

double param(const char *name, double def) {
  const char *v = getenv(("P_" + string(name)).c_str());
  return v ? atof(v) : def;
}

const double TL = param("TL", 1900);       // constexpr にはできない
const double T0 = param("T0", 100), T1 = param("T1", 1);
const int WIDTH = param("WIDTH", 500);     // int も double 経由で受ける

手で 1 回だけ試すときは P_T0=50 ./a.out < tools/in/0000.txt のように直接渡してもよい。

テンプレに入っている名前

sa.cpp

TL 打ち切り (ms)
T0 開始温度
T1 終了温度

beam.cpp

TL 打ち切り (ms)
WIDTH ビーム幅
W1 特徴量 f1 の重み

chokudai.cpp

TL 打ち切り (ms)

評価関数の重み

評価関数に何を入れるか迷ったら、思いついた特徴量を全部足して重みを tune.py に任せる。効かない特徴量は重みが 0 付近に寄るので、それを見て消せばよい。

const double W1 = param("W1", 0), W2 = param("W2", 0), W3 = param("W3", 0);

// 候補を作るところ
double eval = score + W1 * f1 + W2 * f2 + W3 * f3;
cand.pb({eval, hash, (int)i, (int)d});
python3 ~/kyopro/ahc/tune.py W1=-5:5 W2=-5:5 W3=-5:5 WIDTH=200 TL=800 -s 0-29 -n 60
  • 重みの符号がわからないときは -5:5 のように 0 をまたぐ一様の範囲にする。:log は正の値にしか使えない。
  • 特徴量の大きさをだいたいそろえておく (score と同じくらいの桁にする) と、範囲を決めやすい。
  • 調整中はビーム幅を固定しておく。幅も一緒に動かすと、時間いっぱいまで広げた幅が選ばれて重みの差が見えにくい。
  • 終盤だけ効く特徴量は、W1 * f1 * (turn / T) のように進み具合を掛けた項を別に作る。

run.py

全 seed を並列に回して、件数・失敗数・平均・合計・最大時間を出す。

指定意味
K=V環境変数 P_K=V として渡す。いくつでも並べられる
-s 0-99seed。0-49、3,7,10-12 のように書ける
-j 6並列数
-c ./a.out実行するコマンド。-c "python3 main.py" も可
--save NAMEseed ごとのスコアを runs/NAME.json に保存
--base NAMEruns/NAME.json と比べて relative と win / lose を出す
--minスコアが小さいほど良い問題
-vseed ごとのスコア・時間・基準との差を全部表示

出力は out/0000.txt、stderr と採点結果は out/0000.err に残る。1 ケース 10 秒を超えると打ち切って失敗にする。

tune.py

最初にコードの既定値で 1 回回して基準にし、seed ごとの基準比の平均 (relative) が一番高い組を探す。毎回「ランダムに 1 点」か「今の最良を少しずらす」のどちらかを試し、終盤ほど細かくずらす。seed の組は全試行で同じ。

書き方探し方
K=lo:hi一様。符号が変わる重みなど
K=lo:hi:log対数で一様。温度や係数など、桁で効く正の値
K=lo:hi:int整数。ビーム幅、近傍の大きさなど
K=V固定。基準の実行にも同じ値を渡す (TL=500 など)
オプション意味
-n 50試行回数 (基準の 1 回は別)
-s 0-29seed
-j 6 / -c / --minrun.py と同じ

1 試行にかかる時間は「TL × seed 数 ÷ 並列数」くらい。TL=500、30 seed、6 並列なら約 2.5 秒で、50 試行で 2 分ほど。

出力の例 (AHC006 で実際に回したもの)

[ 38/40] rel 1.0650 fail 0  T0=71.4324 T1=6.42136 SWAP=0.8 POOL=262
[ 39/40] rel 1.0775 fail 0  T0=121.35 T1=6.42136 SWAP=0.8 POOL=217

別の seed でも確認する (seed 100-199 の基準は 1 回だけ保存すればよい):
  python3 ~/kyopro/ahc/run.py -s 100-199 --save def
  python3 ~/kyopro/ahc/run.py -s 100-199 --base def T0=71.4324 T1=6.69635 SWAP=0.8 POOL=210
コードの既定値に書き戻す:
  param("T0", 71.4324)
  param("T1", 6.69635)
  param("SWAP", 0.8)
  param("POOL", 210)

全試行は runs/tune.tsv に追記される (relative、失敗数、パラメータ)。sort -rn runs/tune.tsv | head で上位を見られる。

結果の読み方

  • relative は seed ごとの「スコア ÷ 基準」の平均。1.02 なら平均 2% 良い。AHC の相対評価に近いので、合計より信用できる。失敗した seed は 0 として数える。
  • win / lose は基準より良かった seed と悪かった seed の数。relative が上がっていても lose が多いときは、一部の seed で大勝ちしているだけのことがある。
  • 同じ seed で選び続けると、その seed に合わせ込んだ値になる。relative 1.01 以下の差は、別の seed で確かめるまで信用しない。
  • 時間で打ち切る解法は実行ごとにスコアが揺れる。同じ設定を 2 回回して、揺れの幅を一度見ておく。
並列数と TL

-j を増やしすぎると 1 ケースあたりの計算量が減ってスコアが下がる (12 スレッドでも物理コアは 6 程度)。比べる実行どうしは同じ -j にそろえる。温度の最適値は TL によって少し変わるので、短い TL で探した値は最後に元の TL で確かめる。

困ったとき

症状見るところ
FAIL が出るout/XXXX.err を開く。assert 落ち、出力形式の誤り、10 秒超えのどれか。Score = が見つからなくても FAIL になる
tools/in/0100.txt がないその seed の入力を作っていない。tools で seq 0 199 > seeds.txt のあと cargo run -r --bin gen seeds.txt。100〜199 だけを書くと 0000 から上書きされる
スコアが全部同じparam() の名前と K=V の綴りが合っているか。P_ は付けずに書く
小さいほど良い問題run.py と tune.py の両方に --min を付ける
「既定値より良いものは見つからなかった」既定値がすでに良いか、範囲が狭い・ずれている。範囲を広げるか、効いていない値を外す
tester と vis を取り違えるtools/target/release/tester があると必ず tester を使う。非インタラクティブの問題でできていたら消す

AHC006 で試した記録

2026-10-17 に ~/kyopro/dry/ahc006/a で一通り回した (提出なし)。解法は sa.cpp を元にした焼きなましで、近傍は「1 点を別の位置へ移す」と「選んだ注文を中心に近い候補と入れ替える」の 2 つ。

手順結果
基準 (T0=100 T1=1 SWAP=0.3 POOL=300)seed 0-49 平均 17980
手で T0=30relative 0.981、20 勝 30 敗。悪化
tune.py 40 試行 (TL=500、seed 0-29)約 2 分。relative 1.083

  • tune 中の +8.3% は別の seed では +3.5% 前後に縮んだ。tune の数字は割り引いて読み、必ず別の seed で確かめる。
  • SWAP が範囲の上限 0.8 に張り付いた。上限や下限に張り付いた値は範囲を広げて回し直す。
  • ツールの gen は行番号でファイル名を付ける (上の「別の seed で確かめる」を参照)。
