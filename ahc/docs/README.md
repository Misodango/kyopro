## 最初の10分: 紙にこの6行を書く

1. **本当の目的**: 最大化 / 最小化。何が1増えると何点変わるか。全件達成前後で式が切り替わるか。
2. **絶対条件**: 操作数、予算、連結、重なり、順序、全対象処理、入出力プロトコル。
3. **すぐ出せる解**: 1個ずつ処理、全て単独、通路を固定など、検証しやすい構成。
4. **探索変数**: 順序 / 採用集合 / 割当 / 座標 / 木 / 操作列 / 少数パラメータ。
5. **変数から解を作る方法**: 貪欲、BFS・Dijkstra、DP、マッチング、シミュレーション。
6. **1回だけ改善する方法**: 何を外して何を入れるか。その後どこまで再計算するか。

「全部を直接探索する」以外に、**順序だけ探索して、その順で合法な解を構成できないか**を一度考える。

## 手法を選ぶ3つの質問

**完成解を簡単に作り直せるか。** 作れるなら、順序・集合・割当の山登り / SA が候補。難しい合法性は構成器に集める。

**一手ずつ決める意味があり、途中の有望さを比べられるか。** 比べられるならビーム。比較する層は「同じ手数」に限らず、同じ時刻・処理数・走査位置でもよい。

**大半を固定すると、小さな部分は正確に解けるか。** 解けるなら、外側で対象を選び、内側を最短路・DP・全探索で修復する。SAにするときも、近傍1回を「破壊＋修復」と考える。

どれも難しいなら、乱択貪欲を複数回実行し、構成順・候補の残し方・評価を改善する。ビームとSAを両方実装する必要はない。

## 詰まったら、この順に確認する

- **点が付かない** → 評価関数より先に、合法性・必須条件・スコアの分岐を確認。
- **同じ解ばかり** → 乱数seedより先に、構成順・対象選択・近傍で動く変数を確認。
- **幅を増やしても伸びない** → 候補生成・中間評価・状態の重複と偏りを確認。
- **SAがほぼ動かない** → 無効近傍率、同一解への修復率、悪化幅と温度の単位を確認。
- **見かけの点だけ伸びる** → 構成器の近似と、実際の出力をリプレイした点を比較。
