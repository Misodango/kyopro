## 2. beam.cpp の置き換え順

1. `State` に将来の合法手・報酬を決める情報を入れる。例の `pos + vis` に当たるものを特定する。
2. `initState` から合法な状態を作る。
3. `nextPos` 相当を「候補生成＋合法性判定」にする。分岐が多いなら、全候補生成の前に絞る。
4. `Cand.eval` は途中の有望さ。完成解の `score` と同じとは限らない。
5. `Cand.hash` は採用後のStateと一致させる。資源や時刻を省ける条件を確認する。
6. `applyAction` と候補側の差分計算が、同じ遷移を表すようにする。
7. 途中打切りでも提出できる完成解を保存し、復元・リプレイして返す。

### 移植時に気をつける点

**幅を増やしても、幅1の解以上になる数学的保証はない。** 広いビームでは新しく現れた候補が、貪欲の枝を途中で押し出せる。例題の `score >= greedy` というassertは、一般問題の保証に置き換えない。幅1の完成解を独立に保存して、実際に検証したスコアが良い方を返す。

**時間切れ時の途中状態は、提出可能な解とは限らない。** 例題はT手の出力をassertしている一方、探索側には層の途中でなくても早期打切りがある。問題で全処理・固定長出力が必要なら、貪欲補完か既存の完成解へ戻す処理が必要。補完・検証・復元・出力の時間を先に予約し、その分早く探索を打ち切る。全候補の生成・sortが長い場合、層の終わりだけの時刻確認では遅い。

**hash重複除去と、多様性の確保は別の機能。** 異なるhashでも、同じ方面・同じ戦略に偏り得る。必要なら終点、資源帯、初手、被覆パターンなどで候補枠を分ける。64bit hashの一致は厳密な状態同一性の証明ではなく、衝突もあり得る。

**終端条件を問題に合わせる。** 固定T手、任意時刻終了、目標達成終了を区別する。最も深い状態が最良とは限らない。空候補、初期状態ですでに完了、合法手なしでも返却先を用意する。

## 3. sa.cpp の置き換え順

1. `State` を合法な完成解、または完成解を作る種（順序・割当など）にする。
2. `initState` と `calcScore` を先に完成させる。
3. 最初はcopy→変更→全評価で、1種類の近傍を確実に動かす。
4. 差分評価にするなら、何が変わるかを列挙してから `delta` を書く。
5. 無効近傍、棄却時の復元、最良合法解の保存を確認する。
6. 実際の悪化幅から温度を決め、同じ予算の山登りと比較する。

### 2-opt の式がそのまま使える条件

例題は対称距離の巡回路なので、区間を反転しても内部の辺の長さは同じ。境界の4本だけでdeltaを計算できる。**有向距離・順序依存の費用・集荷後配達・時間窓・積載・燃料**がある場合は、内部の向き、順序制約、後続への影響を再評価する必要がある。

`reverse` の後に先行関係を壊していたら、正しい距離deltaでも不正解になる。最初の近傍は、合法な範囲内の1点挿入や、依存する対象を一組にした移動の方が作りやすい場合がある。

### 温度は無次元の強さではない

最大化で悪化幅を `d > 0` とすると、悪化手の受理確率は `exp(-d/T)`。幅dを確率pで受理したいなら `T = -d / log(p)`。たとえばd=100、p=0.5ならTは約144。

目的値を100倍したら、同じ動きをさせる温度も100倍必要。近傍を変えたときもdelta分布は変わる。例題の温度を今日の問題へ固定値としてコピーしない。

評価に時変ペナルティを入れるなら、同じ時刻の係数で新旧両方を比較する。以前の係数で保存した `cur.score` と今の係数の候補点を引いてはいけない。

## 4. chokudai.cpp の置き換え時

深さごとに候補を残すので、その周回では未展開のままキューに残した枝を、後の周回で展開できる。一方で状態や履歴が多く残り、メモリ量と探索後の解放も時間予算へ入る。[既存README](https://github.com/Misodango/kyopro/blob/ccd1d37a8bb2ef7127ea9898a7ba565841da9171/ahc/README.md) のメモリ・時間値は例題での記録であり、本番の余裕を保証しない。

深さをまたいで同一hashを使うなら、手数・残時間などによる将来の違いを識別する。同じ構造でも累積コストが違う場合は、単純に「一度展開したhashを全て捨てる」でよいか検討する。優越条件が保証できなければ、最良コストの更新や再展開の扱いが必要。

## 5. 仕上げに合わせる4つの値

| 値 | 意味 |
|---|---|
| `official_score` | 出力を採点した本当の点 |
| `search_eval` | ビーム選別/SA受理に使う値 |
| `current_solution` | 探索が今いる場所。悪化や一時違反を含み得る |
| `best_valid_solution` | ここまでに確認した最良の合法な完成解 |

これらを同じ変数で扱わないことが、状態・近傍の工夫を安全に追加する土台になる。
